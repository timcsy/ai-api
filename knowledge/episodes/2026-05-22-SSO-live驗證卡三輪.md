# 2026-05-22 · Google OIDC live 驗證卡三輪

## 為何（why）
階段 2 認證要真機驗 Google OIDC。整段 SSO 卡住，錯誤只說 `invalid_credentials` /
「The token is not valid as it was issued in the future」。

## 怎麼（how / 追了三輪才發現兩個獨立問題疊在一起）
- (a) 本機時鐘比 Google 慢 ~3 秒，`claims.validate()` 不容忍未來 `iat`。
- (b) OIDC callback 在 `delete(state_row)` + `flush()` **之後**才讀 `code_verifier`/`nonce`，authlib 拿到空值。
- 修法：`validate(leeway=60)` + delete 前先 cache 欄位。（commit `ce3d640`）

## 用了哪些概念
「讀後即刪的短期 token/state 要先 cache 成 local」「收外部 JWT 一定設 clock-skew leeway ≥30s」。

## 結果
兩條蒸餾成通則，收於 [`history/lessons-archive.md`](../history/lessons-archive.md)。此類「真機才暴露、CI mock
測不出」的坑後來反覆出現（見 experience「新增對外連線/新上游行為要真機才暴露」）。
