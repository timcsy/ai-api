# 2026-07-02 · 研習衝量被誤隔離，逼出異常偵測 v2

## 為何（why）
剛遷移新叢集/辦研習時 baseline 稀疏，比例門檻低到荒謬——實測某分配 baseline 僅 **3.65 次/hr**，研習示範
**103 次**就觸發隔離（10× = 36.5 即擋），正常使用者吃 403；而辦活動前 admin **無法自己**暫停自動隔離、只能靠
工程師。這是 spec 054（階段 40）的驅動場景。

## 怎麼（how / 為何這樣選）
- 「平時判斷別那麼嚴」的正解**不是無腦調鬆倍數**（會放過真濫用），而是「證據不足就不用脆弱的比例規則」：
  `baseline_total < baseline_min_calls`（預設 200）時改用**絕對量門檻**；但用量真離譜（≥ 絕對門檻）稀疏 baseline
  也照抓。
- 敢把「暫停自動隔離」交給 admin 的關鍵論據：硬天花板（token + 成本配額）本就存在，異常偵測只是第二層預警、
  暫停風險有界。誤判彎路：調高倍數 / 暫停 cronjob（易忘開回）皆棄。
- 設定搬 DB 單例（`anomaly_config` lazy-seed），env→DB 模式第三次套用。

## 用了哪些概念
「相對/比例門檻需足量樣本才可信」；「保護型自動化要給 admin 暫停旋鈕（含到期自動恢復）」；env→DB 單例。
