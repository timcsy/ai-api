# 2026-06-08 · Codex 一鍵安裝三平台真機驗收（bare slug 三連坑）

## 為何（why）
階段 19（spec 029）Windows/macOS/Linux 三平台真機驗收——前置客戶端（Codex）自帶模型 catalog 用 bare slug
（`gpt-5.4`），我們用 `provider/slug`（`azure/gpt-5.4`），命名空間對不上。

## 怎麼（how / 三個接連的坑）
1. 安裝腳本沒 pin `model` → Codex 用它內建預設模型；
2. 就算 pin，Codex `/model` 選單列的是它內建 bare slug、看不到 `azure/gpt-5.4` → 成員選不到、送出又 mismatch；
3. `/model` 是 client 本機切換、選的當下不連伺服器 → 無法「選到就擋」。
- 對策：proxy 層做**雙向對齊**（接受 client 的 bare slug、對外仍用正規 slug；歧義就不 alias）；pin 時優先
  bare slug；「選的當下無法擋」的互動退而給清楚錯誤訊息（rev 60→62）。

## 用了哪些概念
「前置客戶端自帶目錄時，gateway 命名空間要能被它的 picker 看見」；正規 slug/provider 前綴是 litellm 路由必需、
不能為了好看拿掉。此坑在階段 36 Copilot 又以「id 空白 → 模型不在範圍」變體重現（`/v1/models` 的 id = 正規 slug）。

## 結果
三平台真機驗收完成；教訓收於 `f9a7254` experience。桌面版措辭也基於同日實測由「不建議」改「一鍵安裝後也能用」。
