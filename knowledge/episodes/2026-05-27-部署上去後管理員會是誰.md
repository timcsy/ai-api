# 2026-05-27 · 「部署上去後管理員會是誰？」

## 為何（why）
使用者一句問話戳破了「pod healthy ＝ 部署完成」的錯覺——這句話直接催生了 spec 017（階段 8）。

## 怎麼（how）
一查發現：全新 DB 沒有任何 admin member、後台 UI 只吃 session、從不送 bootstrap token（前端刻意如此）、
OIDC 自助註冊者一律非 admin → **部署完成卻沒人進得了後台**；唯一能動的是預設值公開已知的 bootstrap token
（等於後門）。逼出兩件事：首位 admin 佈建是部署一等公民（idempotent CLI + helm pre-upgrade hook）、
不安全預設 token 要 fail-fast；並順勢把 001 拿來保護 admin API 的 bootstrap token 重新定位為 break-glass。

## 用了哪些概念
「部署完成 ≠ 跑得起來」「安全預設啟動時 fail-fast」「沿用既有環境訊號（COOKIE_SECURE）比新增旗標省心」。
