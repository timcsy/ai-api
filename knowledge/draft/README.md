# draft — 短期記憶

從討論卸下來、還不值得定案的東西。**一個主題一個檔**：`YYYY-MM-DD-主題.md`（用 `-` 不用空白——空白會讓指向它的連結斷掉一半），加一行「怎麼冒出來的」。

檔名兩半各有用處：**日期**是時間線索（「上個月那批」），也標記這是一次討論的快照；**主題**是語義線索（「關於 X 的那個」）。兩個都在檔名，不必打開就找得到。

## 運作方式（像短期記憶）
- **一個主題塊一個檔**，連它的脈絡一起——不拆成零碎便利貼。記憶的單位是「一段」，不是原子。
- **同一主題下次再聊 → 開新檔（新日期）**，不覆蓋舊的：同主題累積出多個快照，那個累積本身就是「該固化」的信號。
- **預設衰減**：沒被再碰的主題會淡出——遺忘是功能，不是失敗。大部分本來就該淡出，只有少數固化。
- **被使用救起**：一個你反覆回來看的主題，證明它該固化 → 蒸餾進三檔 / concepts，然後刪掉這裡的檔。
- **新近度看 git**（最久沒碰的＝該處理的候選），不手動維護。
- **三種出口，都離開 draft**：固化 · 放手（刪） · 否決（在 `history/` 留墓碑）。

## judge 怎麼巡檢
用 git 新近度撈出最久沒碰的主題，逐一判「救起（固化）or 放手（淡出）」。判準是**新近度 + 頻率，不是年齡**——一個老但你一直回頭看的主題是活的；一個新但再也沒碰過的不是。
