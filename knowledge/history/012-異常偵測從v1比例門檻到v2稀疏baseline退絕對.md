# 012：異常偵測從 v1（比例門檻、無 admin 控制）到 v2（稀疏 baseline 退絕對 + admin 可暫停）
> 日期：2026-07-02

## 轉移
- 舊（superseded）：v1 純比例門檻（baseline × 倍數），無 admin 控制、設定寫在 env。
- 新（spec 054 / 階段 40，migration 0022）：① `baseline_total < baseline_min_calls`（預設 200）時不套比例、
  改**絕對量門檻**；② 設定搬 DB 單例（`anomaly_config` lazy-seed）＝單一真理；③ admin 可自助**暫停/關閉**自動
  隔離（`pause_until` 到期讀時自動恢復、不需背景任務）。

## 為什麼變
baseline 稀疏（剛遷移新叢集、辦研習）時比例門檻低到荒謬——實測某分配 baseline 僅 3.65 次/hr，研習示範 103 次
就觸發隔離、正常人吃 403，且辦活動前 admin **無法自助**暫停、只能靠工程師。**治本不是無腦調鬆倍數**（會放過
真濫用），而是「證據不足就不用脆弱的比例規則」——相對/比例門檻在樣本不足時本就不可信。敢把暫停權交給 admin
的關鍵論據：硬天花板（token + 成本配額）本就存在，異常偵測只是第二層預警、暫停風險有界。
**誤判彎路**：調高倍數 / 暫停 cronjob（工程師介入、易忘開回）皆棄。

## 狀態
✅ 已採用。不執法期間照掃描/記錄/可告警（`enforced=false`）但不隔離；停用只停「新增」隔離、已隔離者需各自解除。
env→DB 單例模式第三次套用。服務型分配既有豁免不變。
