# 可見性 = 供給存在 ∩ 授權允許（雙道獨立閘）

**可判斷主張**：拿一個「某成員看不看得到某 model」的判斷問「它是不是同時要求 (a) 該 provider 至少有一筆
active credential **且** (b) 通過 tag access policy，兩道獨立閘缺一不可？」——是，屬這個概念；只看其中
一道，就是反例。

## 一句話

一個 model 對某成員可見 ⇔（credential gate：admin 根本接了這家）**且**（access policy：接了且授權給你）。

## 為什麼是它（剪枝力）

- **安全組合性**：credential gate 隱藏「admin 沒接這家」、access policy 是「接了但不給你」；兩者 credential
  來源不同——env fallback 能讓「呼叫上游」成功，卻**不算** access policy 的「供給存在」（存取只認 DB
  `provider_credentials`，不認 env）。這條差異曾讓 `/v1/responses` 一直回 `model_forbidden`。
- **deny 優先於 allow**：member tag 同時命中 `allowed_tags` 與 `denied_tags` 時 deny 生效；診斷要明確標「是 deny
  先生效，非 allow 不命中」。
- **proxy 呼叫時再做防禦性二次檢查**，不信任前端過濾。
- auto-tag 自助領取、`/v1/models`（依金鑰 scope 而非目錄過濾）都只是這機制的**新入口**，不改此閘。

## 投影到三觀點

- **principles**：原則 2（可追蹤性）+ 原則 5（單一治理路徑）+ 原則 1（`/v1/models` 的 scope 來源 = 金鑰授權本身）。
- **vision**：〈核心想法〉「動態 catalog 可見性」、〈架構〉存取政策。
- **history / experience**：「能呼叫上游 ≠ 通過存取政策」教訓；`005-存取治理...單一真理.md`。
