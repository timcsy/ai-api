# 概念

從知識庫蒸餾出的母概念。一個檔放一個反覆出現的概念，以及它在三視角的投影。核心檔只留指向這裡的指針（透過 Key Extensions 表）；細節放這裡。

## 什麼東西夠格在這裡開一個檔
- 它在**三個視角都投得出影**。只強在一面 → 還只是一條教訓或原則，留在 `draft/`。
- 它當母概念有**剪枝力**：能解釋或預測它的子情況。空泛到什麼都裝 = 壞抽象。

## 名字取成斷言，不要取成名詞
`複述一份真相就是排定它過期的日子.md` 勝過 `重複.md`；`看過不算被看見才算.md` 勝過 `可觀察性.md`。

名詞只告訴你東西該**歸**到哪；斷言讓你**判**——把一段文字拿去對那個名字，就知道它該不該進來。那就是上面的剪枝力測試，在命名當下就跑，而不是半年後才發現這個概念什麼都抓不住。

檔名跟著知識庫的語言，並用 `-` 不用空白（空白會讓 `%20` 編碼版和字面版的連結對不上，指向這個檔的連結會有一半悄悄斷掉）。

## 保持收斂
寧可**少數**母概念，不要一堆散的。概念變多時，往**上**找它們共同的母概念——別往下挖更多資料夾。
