# Feature Specification: 異常偵測 v2——管理員可暫時關閉自動隔離 + 稀疏 baseline 聰明放寬 + 門檻可調 + 解除更好找

**Feature Branch**: `054-anomaly-controls`
**Created**: 2026-07-02
**Status**: Draft
**Input**: User description: "長久之計；管理員也有權限暫時關閉隔離機制；平時判斷不要那麼嚴格；解除警報功能"

## 背景與問題

系統會依「近 1 小時呼叫量 vs 近 24h baseline」自動把疑似異常的分配**隔離**（403 擋下），保護共用資源不被跑掉的腳本燒爆。但兩個痛點反覆出現：

1. **誤判計畫性/正常衝量**：baseline 稀疏時（剛遷移、新開站、辦研習衝量），比例門檻低到荒謬——實測某分配 baseline 僅 3.65 次/hr，研習示範 103 次就被隔離（10×=36.5 即觸發），正常使用者被無預警擋下。違反原則 6（可達性）。
2. **管理員缺乏自助控制**：辦活動前無法**自己**暫時關閉自動隔離、只能靠工程師改設定或暫停排程；解除隔離的功能雖存在，但藏在分配頁選單裡、不好找。

本功能把異常偵測升級為「**聰明、可控、可稽核**」：管理員能自助暫停自動隔離（含到期自動恢復）、偵測在證據不足時聰明放寬（但真濫用照抓）、門檻可調、解除更好觸及。硬天花板（token/成本配額）本就存在，異常偵測是第二層預警，故「暫停自動隔離」的風險有界。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理員自助暫時關閉/暫停自動隔離（Priority: P1）

管理員在辦研習或已知高用量活動前，於管理介面把「自動隔離」關閉、或設定「暫停自動隔離到某個時間、到期自動恢復」；期間任何使用者都不會被自動隔離擋下，全程不需工程師或重部署。

**Why this priority**: 這是使用者的核心訴求——把「要不要在此期間執法」的控制權交還給管理員自助（原則 6）。有它，活動當天就有保險。

**Independent Test**: 於介面關閉自動隔離 → 製造一個平常會觸發隔離的用量 → 確認該分配**不被隔離**、使用者照常呼叫；再開回 → 確認恢復偵測。

**Acceptance Scenarios**:

1. **Given** 管理員在異常偵測設定頁，**When** 把「自動隔離」切為關閉並儲存，**Then** 之後的偵測掃描**不再隔離任何分配**（仍記錄/可告警），介面明確顯示「自動隔離：已停用」。
2. **Given** 管理員設定「暫停自動隔離到 today 18:00」，**When** 到達 18:00 後的下一次掃描，**Then** 系統**自動恢復**啟用、無需人工，且期間曾被略過的偵測恢復正常。
3. **Given** 自動隔離為停用中，**When** 管理員查看設定頁，**Then** 清楚顯示停用狀態與（若有）到期恢復時間。
4. **Given** 管理員變更此開關/暫停，**Then** 留下稽核（誰、何時、改成什麼）。

---

### User Story 2 - 稀疏 baseline 時聰明放寬，但真爆量照抓（Priority: P1）

當一個分配的歷史 baseline 樣本太少（不足以構成可信基準）時，系統不套用「倍數比例」規則、改用「絕對量」門檻判斷，避免對剛遷移/新站/計畫性衝量誤判；但只要用量真的離譜地高（超過絕對門檻），仍照樣隔離。

**Why this priority**: 這是「平時判斷不要那麼嚴格」的**治本**——不是無腦調鬆倍數（會放過真濫用），而是「證據不足就不用脆弱的比例規則」。與 US1 並列 P1（US1 是開關、US2 是常態品質）。

**Independent Test**: 造一個 baseline 極稀疏的分配 → 給一個「以比例算會觸發、但遠低於絕對門檻」的用量 → 確認**不被隔離**；再給一個「超過絕對門檻」的用量 → 確認**仍被隔離**。

**Acceptance Scenarios**:

1. **Given** 某分配近 24h baseline 呼叫數低於「最小可信樣本數」，**When** 近 1h 用量以比例算會超標、但未達絕對門檻，**Then** 系統**不隔離**（比例規則不適用於稀疏 baseline）。
2. **Given** 同上稀疏 baseline，**When** 近 1h 用量達到絕對門檻，**Then** 系統**仍隔離**（真爆量不因放寬而漏抓）。
3. **Given** baseline 樣本充足的分配，**When** 近 1h 用量達到 baseline 的設定倍數，**Then** 比例規則照常適用、隔離。

---

### User Story 3 - 解除隔離更好找（首頁一鍵解除）（Priority: P2）

管理員在首頁看到「已隔離 N 筆」提示時，能直接一鍵解除，而不必到分配頁逐筆找選單。

**Why this priority**: 解除能力已存在但不夠顯眼；讓「發現→解除」變成 1–2 次點擊，降低使用者被卡住的時間。依賴既有解除能力。

**Independent Test**: 造一筆被隔離的分配 → 於首頁提示直接解除 → 確認該分配恢復可用、且記稽核。

**Acceptance Scenarios**:

1. **Given** 有分配被隔離，**When** 管理員在首頁提示處按「解除」，**Then** 該分配恢復為可用、提示計數更新、留稽核。
2. **Given** 被隔離的分配，**When** 管理員檢視，**Then** 能看到**隔離原因**（近 1h 次數 / baseline / 觸發規則）以判斷是否誤判。

---

### User Story 4 - 門檻可由設定調整（Priority: P3）

管理員或維運能調整偵測門檻（比例倍數、最小觸發呼叫數、絕對門檻、baseline 最小可信樣本數），不需改碼重部署；每座叢集可各自拿捏。

**Why this priority**: 讓拿捏鬆緊有旋鈕（尤其剛遷移的新叢集 baseline 低）。加分項，非阻塞主要價值。

**Independent Test**: 調整某門檻值 → 確認下一次偵測依新值判斷。

**Acceptance Scenarios**:

1. **Given** 管理員把「比例倍數」調高，**When** 下一次偵測，**Then** 依新倍數判斷（原本會隔離的邊界情況不再隔離）。
2. **Given** 非法門檻輸入（負數/空），**Then** 被擋下並說明。

### Edge Cases

- **暫停到期**：到期時間已過 → 等同「啟用」；下一次掃描即恢復偵測。
- **停用期間的既有隔離**：關閉自動隔離只停「**新增**隔離」，已被隔離者維持隔離（需管理員各自解除）——介面應講清楚，避免誤以為關閉會自動全部放行。
- **baseline 恰等於最小樣本門檻**：定義為「達標即適用比例規則」（邊界明確、可測）。
- **服務型分配**：既有豁免不變（by-design 爆量的 agent/服務分配本就不納入）。
- **首次未設定過**：自動隔離預設**啟用**、門檻沿用現行值——搬移/上線不改變現狀。
- **多管理員並改**：設定為單一真理，後寫覆蓋且留稽核。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理員 MUST 能自助啟用/停用「自動隔離」，儲存後即時生效於後續偵測，不需工程師或重部署。
- **FR-002**: 管理員 MUST 能設定「暫停自動隔離至某時間」，系統於到期後**自動恢復**啟用，無需人工。
- **FR-003**: 自動隔離停用/暫停期間，偵測 MUST 仍執行並記錄（可告警），但 MUST NOT 對任何分配執行隔離。
- **FR-004**: 當分配的 baseline 樣本數低於「最小可信樣本數」時，系統 MUST NOT 套用比例規則，改以絕對門檻判斷（避免稀疏 baseline 誤判）。
- **FR-005**: 即使 baseline 稀疏，用量達絕對門檻時系統 MUST 仍隔離（放寬不得犧牲對真濫用的防護）。
- **FR-006**: 偵測門檻（比例倍數、最小觸發呼叫數、絕對門檻、baseline 最小可信樣本數）MUST 可經設定調整、不需改碼重部署。
- **FR-007**: 管理員 MUST 能在「已隔離」提示處直接解除隔離（把既有解除能力提升為 ≤2 次點擊可達）。
- **FR-008**: 開關、暫停、門檻、解除等變更 MUST 留稽核（操作者、時間、內容）。
- **FR-009**: 介面 MUST 清楚顯示目前自動隔離狀態（啟用/停用/暫停中含到期時間）。
- **FR-010**: 首次（未設定過）MUST 沿用現況——自動隔離預設啟用、門檻沿用部署層現值，不因本功能改變現狀。
- **FR-011**: 被隔離分配 MUST 可查得隔離原因（近 1h 次數、baseline、觸發規則），供判斷誤判。

### Key Entities *(include if feature involves data)*

- **異常偵測設定（Anomaly Config）**：平台層單例設定。屬性：自動隔離啟用旗標、暫停恢復時間（可空；非空且未到＝暫停中，過期＝啟用）、門檻組（比例倍數、最小觸發呼叫數、絕對門檻、baseline 最小可信樣本數）、最後更新者/時間。為偵測執行與介面顯示的**單一真理**；未設定時回退至部署層現值。
- **隔離決策（Quarantine Decision）**：既有概念，沿用（近 1h 次數、baseline/hr、觸發規則 ratio/absolute）；本功能新增「稀疏 baseline→絕對門檻」的判斷分支與「停用時略過執法」。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理員能在介面 30 秒內、零工程師介入、零重部署地關閉或暫停自動隔離。
- **SC-002**: 在稀疏 baseline 情境（如研習衝量），正常使用者被自動隔離的誤判**降為 0**。
- **SC-003**: 用量遠超絕對門檻的真爆量**仍 100% 被隔離**（放寬不漏抓）。
- **SC-004**: 管理員從看到「已隔離」提示到完成解除，點擊次數 ≤2。
- **SC-005**: 設定「暫停到某時間」後，到期系統**自動恢復**，無需任何人工操作。
- **SC-006**: 開關/暫停/門檻/解除等所有變更皆可在稽核紀錄追溯。
- **SC-007**: 首次（未設定過）行為與現況一致——不需任何介面操作即維持原偵測行為。

## Assumptions

- **沿用既有前例**：平台層單例設定 + 管理員自助介面（比照通知設定、配額池設定）；解除隔離沿用既有能力（端點/選單），本功能提升其可達性。
- **硬天花板已在**：token 配額 + 成本配額已提供硬上限，異常偵測為第二層預警——故「暫停自動隔離」的風險有界（配額仍擋）。
- **不改判定資料源**：仍以既有呼叫紀錄計算近 1h/baseline；服務型分配既有豁免不變；不改隔離的儲存語意。
- **單一真理**：設定只有一個可改處（管理員介面 / 平台設定）；部署層值僅在「未設定過」時作初始預設，避免雙路 drift（原則 5）。
- **對應願景「異常偵測 v2」**，服務 **原則 6 可達性**（admin 自助控制）、**原則 5 集中管理**（設定單一真理）、**原則 2 可追蹤性**（變更留稽核）。
