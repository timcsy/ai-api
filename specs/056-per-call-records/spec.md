# Feature Specification: 用量可觀測性 v2——逐筆記錄檢視 + 逐筆含成本 + 逐筆呼叫圖表

**Feature Branch**: `056-per-call-records`
**Created**: 2026-07-03
**Status**: Draft
**Input**: User description: "管理員能不能看使用者的每一筆 record；逐筆細節能不能成圖（admin 與成員都要）"

## 背景與問題

平台已有豐富的**彙總**用量可觀測性（依成員／分配／模型／標籤／日的圖表、熱力圖、CSV）。但**逐筆**（單次呼叫）這一層有三個缺口：

1. **管理員看不到逐筆記錄**：後端已有 `逐筆呼叫` 端點，但**管理介面沒有任何頁面**列出「某成員／某分配的每一筆呼叫」。管理員要稽核「這個人到底打了哪些」只能直接打 API。成員看自己的分配詳情倒是看得到逐筆清單——**能力不對稱**。
2. **逐筆記錄看不到成本**：逐筆輸出只帶 tokens／狀態／錯誤，**沒有每筆的花費（$）與數量/單位**（DB 其實有記 `cost_usd`／`quantity`／`unit`）。跨端點（token/頁/張/秒…）時，只有「花費」是共同分母，逐筆卻看不到。
3. **沒有逐筆圖**：所有圖都是時間桶彙總（日/時），**沒有「每筆呼叫一個資料點」的視覺**（例如每次呼叫的花費/延遲散點、逐筆時間軸），難以一眼看出離群的單次呼叫。

本功能補齊逐筆層：**管理員逐筆檢視頁**、**逐筆輸出含成本**、**逐筆呼叫圖表**（管理員看全部、成員看自己）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理員逐筆記錄檢視（Priority: P1）

管理員能在管理介面列出**任一成員／分配**的每一筆呼叫，可依成員、分配、時間範圍、結果（成功/失敗）篩選並翻頁；每筆看得到時間、模型、tokens、**花費**、狀態、（失敗時）錯誤。

**Why this priority**: 這是最主要的缺口——管理員目前在 UI 上完全看不到逐筆，稽核「誰打了什麼」無從下手。

**Independent Test**: 以管理員開逐筆檢視頁，選一個成員/分配 + 時間範圍，看到該範圍內的每一筆呼叫清單（含花費），可翻頁、可依結果篩選。

**Acceptance Scenarios**:

1. **Given** 某成員有多筆呼叫，**When** 管理員在逐筆檢視頁選該成員與時間範圍，**Then** 顯示其每一筆呼叫（時間、模型、tokens、花費、狀態），最新在前、可翻頁。
2. **Given** 逐筆清單，**When** 管理員以「僅失敗」篩選，**Then** 只顯示失敗的呼叫並帶錯誤訊息。
3. **Given** 大量呼叫，**When** 翻頁，**Then** 以穩定游標分頁（不重複、不遺漏）。

---

### User Story 2 - 逐筆記錄含成本與單位（Priority: P1）

每一筆呼叫記錄（管理員與成員雙方）都顯示該筆的**花費（USD）**與**數量/單位**（token/頁/張/秒/字元…），不只 tokens。

**Why this priority**: 跨端點唯一可加總、可比較的共同分母是花費；逐筆沒有成本，稽核與異常定位都少一半資訊。與 US1 並列 P1（US1 的清單要能顯示它）。

**Independent Test**: 對一筆已定價的呼叫，逐筆輸出（admin 與成員）都能看到該筆 `花費` 與 `數量/單位`；未定價的呼叫顯示為無成本。

**Acceptance Scenarios**:

1. **Given** 一筆已定價呼叫，**When** 檢視逐筆（admin 或成員），**Then** 該筆顯示花費（USD）與數量/單位。
2. **Given** 一筆未定價（無 price）呼叫，**Then** 花費顯示為「—/未定價」而非錯誤。
3. **Given** 非 token 端點（如每頁 OCR），**Then** 逐筆顯示其原生數量/單位（頁）與花費。

---

### User Story 3 - 逐筆呼叫圖表（每筆一個點）（Priority: P2）

管理員與成員能看到**逐筆散點/時間軸圖**：x=時間、y=花費（或 tokens），**每個點是一次呼叫**，hover 看該筆細節（模型、tokens、花費、狀態）；管理員可看任一成員/分配、成員看自己。

**Why this priority**: 彙總圖看不出「某一次離群的大呼叫」；逐筆圖讓離群點一眼可見。屬進階可視化，依賴 US1/US2 的逐筆資料（含成本）。

**Independent Test**: 對一段時間的呼叫，逐筆圖每次呼叫顯示一個點，離群的大額呼叫明顯高出、hover 可見其細節。

**Acceptance Scenarios**:

1. **Given** 一段期間的呼叫，**When** 檢視逐筆圖，**Then** 每次呼叫一個點（x=時間、y=花費或 tokens），可切換 y 軸維度。
2. **Given** 某次呼叫明顯較大，**Then** 其點明顯高出、hover 顯示該筆細節。
3. **Given** 成員檢視，**Then** 只看得到自己的逐筆點；管理員可選任一成員/分配。

### Edge Cases

- **筆數龐大**：逐筆清單與圖需有上限/取樣或時間窗（避免一次拉數萬筆）；超過時清楚標示「顯示前 N 筆／此區間」。
- **未定價呼叫**：花費為空（顯示未定價），不可當 0 誤導加總。
- **失敗/串流呼叫**：仍是一筆記錄（tokens 可能為 0），逐筆需能呈現其狀態與（若有）錯誤。
- **權限**：成員逐筆僅限自己的分配；管理員可跨成員。既有授權邊界不放寬。
- **時區**：逐筆時間顯示與既有一致（避免與彙總圖時區不一）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理員 MUST 能在介面檢視任一成員／分配的**逐筆呼叫**清單，可依成員、分配、時間範圍、結果篩選，並以穩定游標翻頁。
- **FR-002**: 逐筆清單每筆 MUST 顯示：時間、模型、tokens（輸入/輸出/合計）、**花費（USD）**、數量/單位、狀態、（失敗時）錯誤。
- **FR-003**: 逐筆輸出（管理員與成員兩條路徑）MUST 包含每筆的**花費**與**數量/單位**；未定價呼叫的花費 MUST 呈現為「未定價/空」而非 0 或錯誤。
- **FR-004**: 系統 MUST 提供**逐筆圖表**（每次呼叫一個資料點；x=時間、y=花費或 tokens、可切換），hover 顯示該筆細節；管理員可選任一成員/分配、成員限自己。
- **FR-005**: 逐筆清單與圖 MUST 對「筆數過大」有明確界線（時間窗或上限 + 標示），避免一次載入過量。
- **FR-006**: 成員逐筆檢視 MUST 僅限自己的分配；管理員可跨成員——既有授權邊界不變。
- **FR-007**: 逐筆呈現（時間、單位、成本語意）MUST 與既有彙總可觀測性一致（時區、未定價語意、單位詞彙）。

### Key Entities *(include if feature involves data)*

- **呼叫記錄（Call Record，逐筆）**：既有實體。本功能把其**成本（`cost_usd`）**與**數量/單位（`quantity`/`unit`）**納入對外逐筆輸出（原本只輸出 tokens/狀態/錯誤）。不新增欄位、不改儲存。
- **逐筆檢視（admin）**：以既有逐筆端點為基礎，補上「依成員/時間/結果」的篩選與管理介面呈現（清單 + 圖）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理員能在介面看到任一成員／分配的每一筆呼叫（含花費），並依時間/結果篩選、翻頁——**全程不需打 API**。
- **SC-002**: 逐筆記錄（admin 與成員）皆顯示每筆花費與數量/單位；未定價呼叫不誤顯為 0。
- **SC-003**: 逐筆圖每次呼叫一個點，離群的大額單次呼叫可一眼辨識、hover 見細節。
- **SC-004**: 成員只看得到自己的逐筆；管理員可跨成員；授權零回歸。
- **SC-005**: 逐筆清單/圖對過大區間有界線，不會一次載入過量而卡頓。

## Assumptions

- **沿用既有逐筆端點與計費資料**：admin `/admin/allocations/{id}/calls`、成員 `/me/allocations/{id}/calls` 已存在；`CallRecord` 已記 `cost_usd`/`quantity`/`unit`（增量②）。本功能主要是**對外輸出補欄位 + 加篩選/介面/圖**，不改儲存、不新增 migration。
- **admin 逐筆入口**：以「依成員或分配 + 時間範圍」查詢為主（可能需要一個彙整跨分配的 admin 逐筆查詢，或沿用逐分配端點 + 前端聚合）；細節於 plan 定。
- **逐筆圖**用既有前端圖表庫（recharts）的散點/時間軸；沿用既有時間範圍選擇器與時區慣例。
- **範圍邊界**：只補逐筆層（清單 + 成本 + 逐筆圖）；**不動**既有彙總圖表、不做匯出格式變更（CSV 可後續）、不改額度/配額顯示（那是另一主題）。
- 對應**原則 2 可追蹤性**（逐筆可稽核、含成本）＋**原則 6 可達性**（管理員自助看逐筆、不必打 API）。
